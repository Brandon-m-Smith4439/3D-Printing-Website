# v0.89 Customer Follow-up Automation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add safe, auditable, idempotent customer follow-up reminders for quote response, deposit, final balance, and owner-marked waiting-on-customer states.

**Architecture:** Keep the current single Railway service and SQLite record store. A pure policy module decides eligibility; a persistent follow-up store records every logical reminder; a small scheduler started from root `instrumentation.ts` runs hourly; the owner UI previews, pauses, and inspects automation without exposing secrets. Existing quote, payment, invoice, notification, audit, auth, and shipping flows remain authoritative.

**Tech Stack:** Next.js 16.3.5 App Router, React 19, TypeScript 5.9, Node 22, SQLite `node:sqlite`, Resend HTTP API, Railway.

**Spec:** `docs/superpowers/specs/2026-09-25-v0.89-customer-follow-up-automation-design.md`

## Global Constraints

- Release version becomes exactly `0.89.0`.
- `CUSTOMER_FOLLOWUPS_ENABLED=false` is the deployment default.
- `CUSTOMER_FOLLOWUPS_INTERVAL_MINUTES=60` is the production default and must be clamped to 15-1440 minutes.
- Automated reminders require a linked verified customer account and effective email opt-in.
- One request receives at most one automated follow-up email in any rolling 24-hour window.
- Priority is final invoice > deposit > quote > generic waiting-on-customer.
- Quote and deposit reminders have at most two stages; final invoice has at most two stages; generic waiting has one stage.
- Existing 50% deposit / 50% final-payment behavior is unchanged.
- No Stripe live-mode change and no EasyPost live-mode change.
- No marketing or promotional content.
- No new queue/database product, worker service, SMS, AI copy, or marketing-template dependency.
- Production rollout keeps automatic sending off until a production Preview/Dry Run is reviewed.

## Review Focus

1. **A customer opts out after a candidate was created but before send:** the sweep must re-check the current account/request preference and skip or cancel instead of sending.
2. **A quote is revised after a reminder record exists:** old-revision records must become canceled/ineligible and must not block the new revision's schedule.
3. **Two reminder types become due together:** only the highest-priority type sends; lower-priority records remain eligible after the 24-hour cooldown.
4. **The process restarts after Resend accepted a send but before local persistence completes:** deterministic application record IDs plus the stable Resend idempotency key must prevent a duplicate send.
5. **The owner enables automation while stale production data exists:** the deployment gate plus disabled persisted master switch and Preview/Dry Run must prevent surprise sends.

- [ ] **Step 4: Implement pure policy**

Create `lib/customer-follow-up-policy.ts`. The implementation must:

- accept `now` as input; never call `new Date()` internally for decisions,
- build candidate IDs from request/type/anchor/revision/stage,
- compute quote stages at 48h and 120h,
- compute deposit stages at 24h and 96h,
- compute invoice stage 1 at sent+24h and stage 2 at due date,
- compute waiting stage at waitingSince+72h,
- block invalid request/customer/preference/control states,
- look at existing follow-up records before returning eligibility,
- apply a rolling 24h request cooldown,
- sort by dueAt then priority, but mark lower-priority same-request candidates deferred when cooldown applies.

Core signatures:

```ts
export type FollowUpPolicyInput = {
  now: Date;
  requests: StoredRequest[];
  quotes: StoredQuote[];
  invoices: FinalInvoiceRecord[];
  accounts: CustomerAccount[];
  controls: RequestFollowUpControl[];
  records: CustomerFollowUpRecord[];
};

export function followUpPriority(type: FollowUpType) {
  return type === "final-invoice" ? 0 : type === "deposit" ? 1 : type === "quote" ? 2 : 3;
}

export function followUpRecordId(input: Pick<FollowUpCandidate, "requestId"|"type"|"anchorId"|"anchorRevision"|"stage">) {
  const suffix = input.type === "final-invoice"
    ? `${input.requestId}:invoice:${input.anchorId}:stage${input.stage}`
    : input.type === "waiting-on-customer"
      ? `${input.requestId}:waiting:${input.anchorId}:stage1`
      : `${input.requestId}:${input.type}:${input.anchorId}:r${input.anchorRevision}:stage${input.stage}`;
  return suffix;
}
```

Reminder body generation stays factual and produces immutable strings such as:

```ts
function quoteBody(requestCode: string) {
  return `Your Mesh Harbor 3D quote for ${requestCode} is ready for review. Sign in to your profile to approve it, decline it, or send a counter offer.`;
}
```

- [ ] **Step 4: Implement sweep**

Algorithm:

1. Return immediately when `CUSTOMER_FOLLOWUPS_ENABLED` is not true.
2. Read persisted owner settings; return when `enabled` is false.
3. Build candidates from fresh data.
4. For due eligible candidates in priority order:
   - re-check current state,
   - materialize deterministic follow-up record if missing,
   - skip if already sent/canceled,
   - skip if `nextAttemptAt` is in the future,
   - persist `sending`,
   - send deterministic in-app notification with `email:false`,
   - call `sendFollowUpEmail`,
   - persist `sent` or `failed`,
   - write system audit.
5. Never send a second candidate for the same request in the same sweep.

Scheduler-level retry delays:
- attempt 1 failure => +1 hour,
- attempt 2 failure => +4 hours,
- attempt 3 failure => exhausted, no `nextAttemptAt`.

- [ ] **Step 5: Implement scheduler**

`lib/customer-follow-up-scheduler.ts`:

```ts
const key = Symbol.for("meshharbor.customerFollowUpScheduler");

export function startCustomerFollowUpScheduler() {
  const globalState = globalThis as typeof globalThis & { [key]?: boolean };
  if (globalState[key]) return;
  globalState[key] = true;

  const minutes = clampInterval(process.env.CUSTOMER_FOLLOWUPS_INTERVAL_MINUTES);
  const first = setTimeout(() => void safeSweep(), 60_000);
  first.unref?.();
  const interval = setInterval(() => void safeSweep(), minutes * 60_000);
  interval.unref?.();
}
```

`safeSweep` catches/logs errors and never crashes the app.
