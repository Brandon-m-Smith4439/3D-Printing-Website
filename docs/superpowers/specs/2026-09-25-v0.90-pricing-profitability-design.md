# V0.90 Pricing & Profitability Design

Date: 2026-09-25
Status: Design approved in conversation; written specification for review
Baseline: main @ ba857f489826b7d3600384f6f800c122008fc918
Target release: v0.90.0

## 1. Purpose

V0.90 gives the owner a reliable, private way to understand what each custom print costs, what the customer is being charged, and the expected or realized contribution profit and margin.

The system must make quoting faster without allowing internal costs to leak into the customer account or public APIs.

The owner uses Bambu Lab filament exclusively. Therefore the built-in material catalog is Bambu-specific, begins from current Bambu Lab US MSRP/reference pricing, and can be overridden by actual Bambu invoice history.

The result is not accounting net profit. It is a direct-cost / contribution-profit model intended to support pricing decisions.

## 2. Goals

1. Maintain a Bambu Lab filament catalog with reference MSRP, spool/refill variant, package weight, cost per gram, and source metadata.
2. Import Bambu Lab invoices so actual discounted purchase prices override MSRP when available.
3. Keep historical material purchase lots so old invoices are not lost when catalog MSRP changes.
4. Calculate estimated direct cost for each quote revision.
5. Calculate actual direct cost after production is completed or nearly completed.
6. Calculate contribution profit and contribution margin without double-counting deposits or final balances.
7. Help the owner choose a profitable quote price while preserving manual control.
8. Support reusable pricing presets and safe reuse of prior quotes/costing.
9. Surface profitability summaries and margin exceptions in the Owner Operations Center.
10. Keep all costing data owner-only.

## 3. Non-goals

V0.90 will not:
- implement full bookkeeping, tax accounting, inventory accounting, depreciation, payroll, or income statements;
- automatically change a customer quote price without owner action;
- expose cost, margin, invoice import, or material purchase information to customers;
- automatically reorder filament;
- infer exact printer electricity cost without an owner-configured machine rate;
- treat customer deposits and final invoices as separate revenue streams;
- require exact physical spool inventory depletion tracking to ship v0.90.

Inventory quantity management can be added later. V0.90 records purchase lots and uses them to derive realistic material cost.

## 4. Security boundary

Internal pricing data must be stored separately from StoredQuote.

Do not add internal material cost, labor cost, machine cost, packaging cost, payment fee, target margin, contribution profit, invoice purchase history, or invoice source data to the customer-visible quote object.

All new costing APIs:
- require owner authentication;
- require same-origin validation for mutations;
- use no-store responses;
- audit material imports and costing changes;
- never return raw invoice files through customer routes.

The existing /api/account/requests route may continue to return the current customer quote fields only.

## 6. Bambu filament catalog

### 6.1 Source policy

Initial catalog is seeded from the Bambu Lab US official store as verified during implementation.

Each catalog row stores:
- current reference MSRP;
- package size;
- refill vs with-spool where the official store distinguishes them;
- source URL;
- verification timestamp.

The implementation must not assume all Bambu products are 1 kg. Examples such as PVA and support material may be sold in 0.5 kg packages.

MSRP reference values are used only when there is no actual purchase history for the matching material/variant.

### 6.2 Required catalog coverage

The seed catalog must cover all Bambu filament families available from the official US filament catalog at implementation time, including at minimum:

PLA:
- PLA Basic
- PLA Matte
- PLA Basic Gradient
- PLA Translucent
- PLA Glow
- PLA Marble
- PLA Sparkle
- PLA Metal
- PLA Galaxy
- PLA Wood
- PLA Silk+
- PLA Silk Dual/Multi Color where currently sold
- PLA-CF
- PLA Aero
- PLA CMYK Lithophane variants/bundle where appropriate for per-gram costing

PETG / PET:
- PETG HF if currently sold
- PETG Translucent
- PETG-CF
- PET-CF

ABS / ASA:
- ABS
- ASA
- ASA Aero

PC:
- PC
- PC FR

TPU:
- TPU for AMS
- TPU 95A HF
- TPU 85A
- TPU 90A

Nylon / engineering:
- PA6-CF
- PA6-GF
- PAHT-CF
- PPA-CF
- any additional currently sold Bambu PA/PPA engineering filament

Support:
- Support for PLA/PETG
- Support for PA/PET if currently sold
- PVA
- any additional currently sold Bambu support filament

If Bambu adds a new family, the catalog supports adding it without schema changes.

### 6.3 Current price examples that informed the design

At design time, official Bambu US sources show that:
- common refill products such as PLA Basic, PLA Matte, PETG variants, and ABS can have different refill / with-spool MSRP and separate bulk pricing;
- specialty PLA products commonly carry higher reference prices than basic PLA;
- ASA, TPU, engineering nylon/carbon-fiber, PVA/support, and PC FR have materially different price points;
- some specialty filaments are sold in package sizes other than 1 kg.

Implementation must re-verify the entire current official catalog immediately before seeding v0.90 rather than relying only on these design-time examples.

## 7. Invoice import workflow

### 7.1 Owner UI

Add Owner -> Pricing & Profitability -> Bambu Purchases.

Actions:
- Import Bambu Invoice
- Review imported invoice
- Post purchase lots
- View purchase history
- Correct a posted import through an audited replacement/correction flow
- Manually add a purchase if a receipt cannot be parsed

Initial supported upload:
- PDF Bambu Lab invoices/receipts
- image invoice support may be added only if existing upload/parser infrastructure can handle it reliably without OCR-heavy design

The original invoice file remains private.

### 7.2 Parse-then-review requirement

No uploaded invoice writes purchase lots immediately.

Flow:
1. owner uploads invoice;
2. validate file through existing private upload protections;
3. parser extracts vendor/order/date/totals and candidate line items;
4. product matcher maps each filament line to a Bambu catalog item;
5. owner sees a review screen;
6. unmatched or ambiguous lines are highlighted;
7. owner corrects mappings if needed;
8. owner explicitly posts the import;
9. immutable purchase lots are created.

### 7.3 Bulk-discount handling

The importer must preserve the actual amount paid.

For each filament line:
- begin with list/line amount;
- subtract direct line discounts;
- allocate order-level discounts proportionally across all eligible purchased line values;
- allocate order-level shipping proportionally when PricingSettings includes shipping in landed material cost;
- allocate nonrecoverable sales tax proportionally when PricingSettings includes tax in landed material cost.

If an order contains non-filament products, order-level discount/shipping/tax allocation must consider the full eligible order value so filament is not unfairly assigned all shared charges.

Free shipping naturally contributes $0.

The result is landed cost per purchased filament unit and landed cost per gram.

### 7.4 Duplicate handling

Reject or require explicit owner override when:
- file hash already exists;
- same Bambu order number is already posted;
- same order + line combination appears already posted.

## 8. Material cost resolution

For each quote material line, resolve cost in this order:

1. Weighted-average actual landed cost from matching posted Bambu purchase lots.
2. Current Bambu catalog MSRP cost per gram.
3. Owner manual fallback cost if the catalog entry has no verified MSRP.

The cost source is displayed in the owner UI:
- Actual purchase average
- Bambu MSRP
- Manual fallback

### 8.1 Weighted-average method

V0.90 uses weighted-average landed unit cost by catalog family + package variant.

It does not attempt FIFO spool depletion in this release.

For a given catalog item:
weighted cost per gram =
sum(landed line cost) / sum(purchased net grams)

The UI also shows:
- latest purchase cost;
- average actual cost;
- MSRP;
- savings vs MSRP.

### 9.2 Suggested price

Suggested price solves for a customer total that reaches the configured contribution-margin target after estimated direct costs and percentage/fixed payment fees.

The calculation must be tested for:
- zero target margin;
- zero payment fees;
- fixed + percentage payment fees;
- high-cost orders;
- rounding to cents.

The system does not auto-send or auto-save suggested price.

## 10. Revenue and fee logic

### 10.1 Revenue

Quoted revenue is the active approved/current quote total once.

Do not add deposit revenue plus final invoice revenue.

Deposit and final invoice records describe collection timing only.

### 10.2 Refunds

Quote revision refunds reduce cash collected but do not create a second expense against the same active quote revenue in the profitability formula.

Historical revision snapshots remain available for audit.

### 10.3 Shipping

Customer shipping charge:
- quote.shippingSelection.rateCents

Internal realized carrier cost:
- shipment.postageCostCents after a label is purchased

Before purchase, estimated shipping internal cost defaults to the selected customer carrier rate unless the owner enters another expected cost.

After a successful label refund, realized postage cost becomes zero for contribution reporting.

### 10.4 Stripe/payment fee estimate

V0.90 stores a configurable fee assumption rather than hardcoding a Stripe fee schedule that could become stale.

When a future exact Stripe balance-transaction fee is available from a trusted API, that may replace the estimate, but v0.90 does not depend on that external lookup.

## 11. Estimate vs actual closeout

Each request can have:
- estimated cost snapshot per quote revision;
- actual cost snapshot for production closeout.

When production reaches Ready or Completed, the owner sees Cost Closeout.

Actions:
- Use Estimates as Actuals
- edit actual grams by material
- edit actual machine hours
- edit actual labor/post-processing
- edit packaging/miscellaneous
- save
- Finalize Costing

EasyPost realized postage is imported automatically when available.

Once finalized:
- historical actual contribution profit is stable;
- later edits require an audited reopen action.

## 12. Presets and quote reuse

### 12.1 Pricing presets

Owner can create/update/delete presets.

Applying a preset fills only owner-costing and optional generic quote defaults.

### 12.2 Reuse previous quote

From a prior request, owner may create a new draft based on:
- customer-facing quote structure;
- material family choices;
- expected grams;
- expected machine/labor time;
- packaging/miscellaneous assumptions.

Never copy:
- customer identity;
- email/phone;
- customer account ID;
- shipping address;
- EasyPost IDs or rates;
- Stripe IDs;
- payment history;
- deposit/final-invoice status;
- queue state;
- tracking;
- private customer-specific notes;
- dates unless owner explicitly enters them.

## 18. Bambu invoice attachments supplied through ChatGPT

When the owner supplies current Bambu invoices in the project conversation, use them as test fixtures/data references to verify the importer and to establish the owner's real purchase-cost history.

Do not commit personal invoice PDFs or personal address/payment information to the public GitHub repository.

Only sanitized synthetic fixtures may be committed to tests.

Actual invoice-derived purchase records belong in the private production database through the owner import workflow.

## 19. Success criteria

V0.90 is complete when:
- all current Bambu filament families have usable MSRP/reference catalog entries;
- owner can import and review Bambu invoices;
- bulk-discounted actual costs become the preferred material-cost basis;
- owner can see cost/profit/margin before sending a quote;
- owner can finalize actual cost after production;
- presets and safe quote reuse work;
- Operations Center summarizes profitability;
- customer/public APIs expose no internal costing;
- all tests/build/browser checks pass;
- Railway production reaches terminal SUCCESS.
