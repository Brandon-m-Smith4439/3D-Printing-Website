# Mesh Harbor product projects

## Owner workflow
1. Open `/owner/business`, choose a business, and add an idea/customer problem. One original product family per project; variants and fixes are revisions within it.
2. Queue the leader plan, process a free template or individually approved paid call, and review it. The bounded coordinator sends reviewed leader notes and project context to role-specific draft jobs. These are independent text tasks using the business's configured provider/model; they share that business's monthly budget. There is no unconstrained tool-using agent swarm.
3. Add market observations with dated source links. The research task evaluates supplied evidence; it has no live browsing tool. Approving a research result for the current project version advances a project with observations to design. Stale research approvals cannot advance changed projects.
4. Develop an original design. Upload a closed STL or generate a simple original tray prototype. Never execute model-generated code on the app server. All files are private and retain SHA-256 identities and change notes.
5. Download the latest file, inspect it in Bambu Studio, slice it and print it. Record exact printer, material, minutes, grams, findings and pass/fail. Structural checks do not establish printability, strength, tolerance, self-intersection freedom or product safety. STL units are assumed mm.
6. Failed tests route to refinement. Describe the failure with measured dimensions/fit findings, delegate a refinement brief, change the design and upload a new revision. Previous tests stay attached to their original file. A new file or re-test invalidates release preparation.
7. After a passing physical test, enter accurate descriptions, estimated costs, prices, finished stock and STL licensing/instructions. Confirm original design rights. Physical price must exceed estimated direct cost; this is a simple estimate, not verified profit accounting.
8. Review separate Products and STLs tabs and the private cart preview. Delegate listing copy. No public listing, payment, inventory reservation, digital delivery or Etsy write is executed by this increment. Preview cart state is in memory only and disappears on reload; changed revisions are removed from it.

## Printer planning inputs
Owner reports one Bambu Lab X2D, with a possible second printer later; all Bambu PLA Matte and PLA Basic colors, some Silk PLA and limited PETG/TPU/ABS/ASA. Availability is 18–24 hours/day. These are owner-supplied inputs, not verified machine specifications. Begin with small original PLA items without supports and batchable variants. Derive actual throughput and margin from slicer/physical tests, allowing setup, failures, maintenance and shipping work. Do not assume demand or acquire bulk stock from search popularity alone.

## Railway setup after approval
The existing production service has one persistent local volume. Web and worker processes must share the same SQLite sidecar; different Railway service volumes do not share files. Do not deploy a second isolated worker service pointed at an unrelated local path. Safest initial release: one web service and a manually triggered worker; a later reviewed process supervisor can run both processes in the same container. A scalable separate worker requires shared storage such as PostgreSQL/object storage and a separate migration plan.

Worker entry point: `node --experimental-strip-types scripts/ai-center-worker.mjs --watch`, with both `AI_CENTER_WORKER_ENABLED=true` and (optionally) `AI_CENTER_COORDINATOR_ENABLED=true`. Both default false. The coordinator creates bounded stage jobs; it never approves spending, drafts, physical tests or release. It is not a marketplace crawler. Free templates are scaffolding, not AI research. Paid AI also cannot browse with the current text-only provider.

Backup the AI sidecar, including its assets, using a SQLite-consistent backup. There is no automatic retention/deletion, asset storage quota or backup scheduler yet. Monitor volume usage; the individual/revision limits are not a global storage limit. Only two initial business workspaces are implemented. Independent digital products currently share this STL-focused workflow; generic ZIP/PDF product delivery and arbitrary businesses remain subsequent work.

## Connections still required
- Etsy: the existing shop was renamed MeshHarbor3D and its tagline/story/logo updated through the signed-in browser. Browser login is not durable API authorization. Register an Etsy app and implement reviewed OAuth/PKCE, least-privilege scopes and encrypted token storage before order/listing/inventory automation. Do not send credentials through chat or commit them. Current official API authentication: https://developers.etsy.com/documentation/essentials/authentication/.
- Market research: authorized Etsy/public search or licensed data adapters, source timestamps and explicit distinction between search/review proxies and actual sales. No verified competitor item sales ranking is available in this build. Our own product-level sales rankings need connected order-line data.
- CAD: prototype generator covers one simple tray family. General CAD generation needs a sandboxed geometry worker, versioned source, automated checks and print tests. Arbitrary model-generated code is not executed here.
- Commerce: approved catalog records/photos, Stripe server-priced checkout with idempotent webhook fulfillment, protected digital downloads, refunds policy, shipping profiles and atomic finished-stock reservations across web/Etsy. Existing quote payments are preserved; no cart checkout is wired to them.
- Public release: resolve/review existing dependency findings, obtain staging evidence, review exact products/prices/files/photos/stock/shipping/license and obtain owner deployment/listing approval. Print-testing approval does not publish a listing.
- Shop finishing: matching banner, real printer/process/product photos, listing sections, shipping and return settings remain to be completed before products go live. No seller photo, reviews, sales, product photos or test results were fabricated.

## AI billing
The owner confirmed a $25/month initial experimentation budget. The app defaults to this amount; saved settings remain configurable. Each business has an aggregate monthly cap and additional individual role caps for leader, research, design/refinement, listings, operations, outreach drafts and product ideas. Role caps default to $10 for compatibility with existing settings; they are ceilings within the aggregate business and workspace budgets, not additional allocations. The provider and model remain shared within each business. Failed calls with uncertain billing retain reservations at all three levels. Budget usage is shown alongside each role's setting.
This app's OpenAI API calls use the API account's billing, not ChatGPT Business seat capacity. Add billing in the OpenAI API dashboard, create a dedicated project key, and store it server-side as `AI_CENTER_OPENAI_API_KEY` through an approved deployment configuration change. Do not paste the key into chat. Use a $25 initial app budget, increase to $50 only after useful measured results. Check current supported model rates before saving prices. Local templates and the tray generator do not call paid AI.

API usage is metered by tokens. Search, image generation or CAD services may have separate charges when later integrated. Railway, Etsy fees, Stripe fees, materials, packaging and shipping are separate from the AI experiment budget. Owner approvals and atomic app reservations remain necessary; app estimates are not provider billing reconciliation. https://developers.openai.com/api/docs/guides/production-best-practices and https://developers.openai.com/api/docs/pricing.

## Verification and limits
Unit tests cover immutable revision/test gates, geometry validation, optimistic version conflicts, bounded delegation and existing spend controls. The local HTTP integration checks owner authentication, origin rejection, asset attachment/no-store headers, unsafe filenames and untested release rejection. No paid AI, live Stripe/Etsy sales, shipment, public listing, production data mutation or deployment was exercised.
